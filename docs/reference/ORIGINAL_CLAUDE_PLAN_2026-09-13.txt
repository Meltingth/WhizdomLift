# LMS-NG backend + API — contracts → P1 gateway agent → P0/P2 server

## Context

The owner-approved plan `docs/backend/LMS_NG_Backend_Implementation_Plan_Whizdom_POC_v1_3.md` (1 Sep 2026) already fixes the architecture: a Python edge agent on the Gateway PC (this machine, `GW-WHZ-01`) publishes MQTT to a server stack on PC #2 (Dell, `LMS-SRV`): EMQX 5 · PostgreSQL 16 · Redis 7 · NestJS API · kiosk web. Phases P0–P6 with Definitions of Done live in `docs/workflow/PHASES.md`. This plan does not redesign that; it makes it real.

What was missing (verified 13 Sep): the four contracts the plan calls "law" (MQTT Topic Spec v1, OpenAPI v1, PostgreSQL Schema v1, UI enums) and the `lms-ng` repo **do not exist anywhere** — not on this machine, not on GitHub. Writing them is the first deliverable and is what "design the API" concretely means.

User decisions (13 Sep 2026):
1. Contracts: write fresh from v1.3.
2. Repo: server code + contracts in a new repo `lms-ng` (local `D:\lms-ng`, `git init` now; user creates `Meltingth/lms-ng` on GitHub later — push the moment a remote exists; "everything is public" rule stands). WhizdomLift stays the Edge repo.
3. Server stack runs on the Dell (PC #2). This PC is the gateway: 7.8 GB RAM, Docker Desktop installed but not running, Node 16 — it must **not** run the stack. Server work is prepared here, executed on the Dell.
4. Order: contracts → **STOP for the user's approval (DRAFT → APPROVED)** → P1 agent (WhizdomLift) → P0/P2 server (lms-ng).
5. W-05 (Lift Service): code 47 displays as floor **44**; B1 and 1 as today; codes 3–46 on W-05 stay uncalibrated (`code N`) until the floor-20 stop test.
6. P1 agent takes over capture for **all of 1, 2, 3, 5 and is prepared for 4** (Lift 4 out of service today).

Reality drift the artifacts must absorb (plan is 12 days old): lifts 1/2/3/5 all run firmware 1.2.2 with `LIFT=n` beacons (Lift 3 no longer needs `--map`; keep it as a feature); Lift 1's VS2 is repaired; Lift 4 disabled; the building floor table is closed (CLAUDE.md §3.4: codes 4, 9, 11 are transit levels); W-05 tops at code 47; a powered-off board on one-way RS485 leaves no marker (gaps detected by time only); `board_ms` wraps at 2^32 and runs 0.78 % slow; real lifts have no door signal and no command path (DRY_RUN permanent).

## Absolute guardrails (CLAUDE.md §4, §6, §13)
- Never write to a serial port; never `OUTPUT` a pin; agent code path must contain no serial write.
- No fake data on `W-01..W-05`; simulated traffic only on the `TEST` site (`S-0x`, tag `SIMULATED`) or Demo Mode (zero persistence).
- Contracts change only with a human decision (CHANGELOG + version bump + CI guard + local edit hook).
- `log_lift.py` CLI behaviour must stay byte-identical (golden test) — it is the capture lifeline.
- Commit + push after every change (WhizdomLift); `lms-ng` pushes as soon as the remote exists.
- Every tool must report what it did (§6.15/§6.19): status files, launcher log, loud refusals.

### A.2 MQTT Topic Spec v1 (plan §2.2 step 4)
Root `lms/v1/{siteId}`, `siteId=whz`; simulator root `lms-sim/v1/test`; Demo Mode never publishes MQTT. `elevatorId` = `W-01..W-05` (natural key everywhere); `gatewayId` = `GW-WHZ-01`. Client id = gatewayId, MQTT 3.1.1/5, clean session, LWT registered at connect.

| Topic | QoS | Retain | Cadence |
|---|---|---|---|
| `lms/v1/whz/telemetry/elevators/{elevatorId}/state` | 1 | yes | every accepted debounced change + board 60 s re-emit / boot baseline (`reemit:true`) |
| `lms/v1/whz/events/elevators/{elevatorId}` | 1 | no | one per changed point per accepted line; lifecycle events |
| `lms/v1/whz/status/gateways/{gatewayId}/birth` | 1 | yes | once per MQTT session |
| `lms/v1/whz/status/gateways/{gatewayId}/heartbeat` | 0 | no | every 10 s |
| `lms/v1/whz/status/gateways/{gatewayId}/will` | 1 | yes | LWT (`reason: LWT`) or clean stop (`SHUTDOWN`) |
| `lms/v1/whz/diagnostics/gateways/{gatewayId}/network` | 0 | no | every 60 s |

Envelope on every payload: `schemaVersion "1.0"`, `gatewayId`, `bootId` (uuid per agent process), `sequence` (int64, monotonic per bootId across all kinds), `eventTime` (PC wall clock at `\n` receipt), `source: live|replay`. Dedupe key `(gatewayId, bootId, sequence)`. Topic elevatorId must equal payload elevatorId.

Payload bodies:
- **state**: `elevatorId, floorRaw (string code — agent sends the code ONLY; backend resolves labels), direction UP|DOWN|IDLE|UNKNOWN, statusPoints {RUNNING, SAFETY_DEVICE (true=closed=normal)[, FIRE_OPERATION, FIRE_RETURN when enabled]}, operatingMode NORMAL|FIRE, dataQuality {rejectedLines, positionResolution 1|2, directionConflict}, raw {maskHex 13-hex, boardMs, port, firmware|null}, reemit`.
- **event**: `elevatorId (null only for IDENTITY_REFUSED), eventType, data` with `eventType` ∈ `SIGNAL_CHANGE {point FLOOR|DIRECTION|RUNNING|SAFETY_DEVICE|FIRE_OPERATION|FIRE_RETURN, prev, next}`, `BOARD_RESTART {lastBoardMs, newBoardMs, reason CLOCK_BACKWARDS|FRESH_BOOT_UNDER_WALL}`, `IDENTITY_REBOUND {fromPort, toPort}`, `IDENTITY_REFUSED {port, claimed}`, `DATA_QUALITY {rejectedLines}`, `SENSOR_VS2_FAULT {state RAISED|CLEARED}`; optional `raw {maskHex, boardMs}`.
- **heartbeat**: `sentAt, uptimeSec, agentVersion, lifts{ elevatorId → {rxtx OK|NO_RXTX, lastLineAt|null, lastLineAgeSec|null, port|null, firmware|null, bindState BOUND|SEARCHING|REFUSED_LIFT0|REFUSED_UNKNOWN|DUPLICATE|HELD_BY_LOGGER|FAILED|NOT_CONNECTED, rejectedLines, reconnects, boardRestarts, queueUnsent} }`. `NOT_CONNECTED` is the configured-but-absent state (Lift 4 today). **birth** = heartbeat + `config {siteId, topicRoot, allowlist {liftId→elevatorId}, mapOverrides, staleAfterSec 90, noRxtxAfterSec 90, heartbeatSec 10, diagnosticsSec 60, debounce{holdMs 60, settleMs 150}, capturePath, hostname, contractsVersion, contractsHash}`. **will**: `{schemaVersion, gatewayId, bootId, reason}`. **diagnostics/network**: per-lift counters `{linesTotal, rejectedLines, reconnects, boardRestarts, identityRebounds, lastLineAt}` + `outbox {unsent, oldestUnsentAgeSec, droppedRows, dbBytes}` + `mqtt {connected, reconnects, publishedTotal, publishFailures}`.
- Thresholds (plan §5.2): rxtx `OK` while any line ≤ 75 s, `NO_RXTX` past 90 s; real lifts `staleAfterSec 90`, simulated 30; `GATEWAY_OFFLINE` = will or 3 missed 10 s heartbeats.

## Deliverable B — P1: `lms_gateway_agent.py` (WhizdomLift)

### B.1 Architecture (one process, all lifts)
```
COM ports (CH340, RS485 one-way)  ── open_quiet(dtr=rts=False), read(1)+read(in_waiting), NEVER write
        ▼ one supervised thread per configured lift (1,2,3,4,5)
LiftReader → CaptureWriter (capture_lift_N.log, EXACT current format) → StreamDebouncer → lift_model → lms_payload → Publisher
PortFinder: single lock-serialized identity scan; refuses LIFT=0, duplicates, ports held by a live logger pid
HeartbeatThread 10 s: heartbeat (direct) · status.json · rxtx ticks     Publisher: OutboxQueue(sqlite) → MqttPublisher | JsonlPublisher | DryRunPublisher
pid files: lms_gateway_agent.pid + capture_lift_<n>.pid per owned lift   stop: STOP_CAPTURE (refuse to start while present; never delete it) | STOP_AGENT
```
A lift that fails to bind (`NOT_CONNECTED`, `REFUSED_*`, `DUPLICATE`, `HELD_BY_LOGGER`) is reported in the heartbeat and retried on backoff; it never stops the others. Lift 4: configured (`W-04`), expected absent → `NOT_CONNECTED`, quiet retry every 5 min, no error spam; the moment its board announces `LIFT=4` it binds with zero config change.
